## 阶段 B — 官网与询盘上线（依赖业务资料 + 服务器）

目标：英文站可访问，表单询盘进入 ERP，运维可备份恢复。

| # | 任务 | 依赖 | 验收 |
|---|------|------|------|
| B1 | 业务方提供真实 `SITE`：邮箱、电话、WhatsApp、工厂地址、Alibaba 店铺链接；核对 FAQ 承诺（付款、样品、港口、回复时效） | 业务输入 | 无占位假信息上线 |
| B2 | 服务器：配置 `Website__AllowedOrigins`、`AllowedHosts`；部署 `soford-website.https.conf`；`nginx -t` 后重载 | 服务器权限 | `nginx -t` 通过；静态站可访问 |
| B3 | 从 ERP 导出 online 商品到 `data/products.js` 并发布 | 有授权账号与商品 | 目录页有真实商品 |
| B4 | 联调：官网提交测试询盘 → ERP「询盘」可见 → 改状态/备注 → 角标正确 | B2 | 端到端记录一条 |
| B5 | 异地备份：配置 `backup-offsite.sh`（OSS/rclone）；在隔离目录做一次恢复（products、accounts、keys、inquiries） | 异地存储 | 恢复后 API 能读、能登录、询盘在 |

**风险**：stepnex 同源站点使部分 CSRF 防护减弱；ICP 完成后尽快切回 `erp.soford.cn` / `www.soford.cn`。

## 阶段 C — 询盘可运营化（需先拍板，约 1–2 周开发）

当前：所有已登录用户共享询盘；JSON 上限约 2 万条淘汰最早记录。

| # | 任务 | 先决条件 | 建议方案 |
|---|------|----------|----------|
| C1 | 归属与协作 | 确认：共享池 vs 按运营账号认领 | 最小改动：状态 + 处理人（已有）+「认领/转交」；冲突用 `expectedUpdatedAt` |
| C2 | 导出 | 确认字段与格式 | Excel/CSV：时间、来源页、产品、联系人、内容、状态、备注、处理人 |
| C3 | 新询盘通知 | 确认渠道 | 优先：ERP 角标（已有）+ 可选邮件/Webhook；不做复杂工单系统 |
| C4 | 归档策略 | 确认留存（如 1 年） | 先做「导出后归档文件 + 主库删除」；满量淘汰前警告；DB 仍后置 |

拍板前不开发 C1–C4 的大改，避免返工。
