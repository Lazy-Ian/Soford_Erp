## 阶段 A：修复已确认问题（全部待执行）

R 编号与 08 一致。

| 编号 | 优先级 | 工作 | 验收 |
|---|---|---|---|
| R1 | P1 | 普通字段统一转义，校验商品单位 | 单位中的 HTML 不创建元素或事件；正常单位显示正确 |
| R2 | P1 | 传递币种并正确格式化；明确跨币种、跨单位排序 | CNY 123 不显示为 USD 123；原始本地商品当前全部为 USD |
| R3 | P1 | 统一结构化交期来源，移除固定兜底 | ERP 3 天与官网一致；缺值显示待确认，正文与摘要无冲突 |
| R4 | P1 | 公司、联系人与条款采用管理员或专门维护权限 | 未获授权运营 PUT 返回 403；前后端权限一致，保留审计 |
| R5 | P1 | 公司事实和业务承诺全站绑定同一来源 | FAQ、首屏、分类、流程、页脚无旧值；清理详情旧承诺与联系人 |
| R6 | P2 | 资料和询盘增加版本冲突保护 | 旧版本保存返回 409，不静默覆盖他人修改 |
| R7 | P2 | 语言切换同步 URL lang 参数 | 带 lang 也能切换，保留商品和筛选参数 |
| R8 | P2 | 未保存提示、加载失败重试、保存期间编辑保护 | 切页有提示；失败结束转圈；响应不覆盖后续输入 |

顺序：R1 → R2/R3 → R4/R5 → R6/R7/R8。针对具体复现补回归检查，保持 Alibaba 写操作安全边界。

以下是业务设计调整建议，区别于阶段 A 的实现问题；具体字段和流程在实施时明确。

| 编号（对应 08） | 工作 | 验收或待明确事项 |

## 阶段 C：提交、部署与验收（对应 08 的 B6）

| 工作 | 验收 |
|---|---|
| 收口提交 | 保留已有工作，按主题整理；不提交 `.env`、App_Data、日志、`.test-results`，不 force-push |
| 本地回归与 CI | 后端、ERP、官网检查通过；逐项验收 R1–R8；核对最终提交的 API、前端/官网、部署配置 CI |
| 业务资料 | 按 [06 清单](06-官网上线资料清单.md) 在 ERP「官网」核实资料，检查全站一致性 |
| 服务器 | 核对实际域名、证书、AllowedHosts、Website__AllowedOrigins，执行 `nginx -t` 后重载 |
| 公开接口 | 目录、单商品详情和 `/public/site` 返回正确状态、JSON 结构与业务内容，不只看首页 200 |
| 询盘闭环 | 提交明确标记的测试询盘 → ERP 可查 → 改状态/备注 → 角标正确；记录测试数据处理方式 |
| 部署 smoke | 补 `/public/site` 检查和失败退出码；当前脚本会真实写入询盘、忽略部分失败，退出 0 不能代表完整验收 |
| 备份恢复 | 异地复制后隔离恢复商品、账号、密钥、用户、询盘及官网资料，确认 API、登录、数据可读 |

人工或外部条件：详细地址、店铺链接与业务承诺核实，服务器访问，异地存储凭证，ICP/域名安排，以及另行授权的真实 Alibaba 写入抽检。官网独立域名方案待确认；`www.soford.cn` 在现有路径部署说明中为国际站保留，不能直接当本次官网切换目标。
