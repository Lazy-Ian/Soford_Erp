# Soford ERP 技术方案

版本：v1.0　日期：2026-09-29　对应需求：[01-产品需求.md](01-产品需求.md)

## 1. 总体架构

```
浏览器 (React 19 + Vite)
   │  /api/*  /openapi/callback   (Cookie 会话)
   ▼
ASP.NET Core 8 Minimal API  ──────────►  Alibaba ICBU OpenAPI
   │                                       https://openapi-api.alibaba.com/rest
   ├─ Endpoints/   路由（按领域分组）
   ├─ Alibaba/     IOP 客户端、签名、Token、报文映射
   ├─ Catalog/     商品模型、仓储、导入、质检、导出
   ├─ Publishing/  后台发布队列、任务存储
   └─ Storage/     原子 JSON 文件存储、.env 加载
   ▼
App_Data/ (products.json, publish-jobs.json, alibaba-token.json(加密), alibaba-api-logs.json, category-attributes.json, exports/)
```

存储继续用 JSON 文件：单管理员、商品量级为千级，不需要引入数据库；统一改为「写临时文件 + 原子替换」并加锁，保证不损坏。

## 2. Alibaba IOP 协议（已用真实 AppKey 验证）

| 项 | 规则 |
|----|------|
| 网关 | `https://openapi-api.alibaba.com/rest` + API 路径，例如 `/alibaba/icbu/product/listing/v2` |
| 公共参数 | `app_key`、`timestamp`（UTC 毫秒）、`sign_method=sha256`、`access_token`（需授权的接口）、`sign` |
| 业务参数 | 顶层字段作为表单参数；对象/数组参数序列化为 JSON 字符串 |
| 签名 | `HEX_UPPER(HMAC_SHA256(secret, apiPath + 排序后拼接的 k1v1k2v2…))`，排除 `sign` 和文件参数 |
| 文件参数 | `multipart/form-data`，不参与签名（图片上传 `image_bytes`） |
| 错误判定 | 顶层 `code` 存在且不为 `"0"` → 网关错误（type: ISV/ISP/SYSTEM）；`result.success=false` 或顶层 `success=false` → 业务错误（`msg_code`/`message`） |
| 授权 | `https://oauth.alibaba.com/authorize?response_type=code&client_id=…&redirect_uri=…&state=…&view=web&sp=icbu` |
| Token | `/auth/token/create`(code)、`/auth/token/refresh`(refresh_token)；返回 `expires_in`、`refresh_expires_in`（秒） |

验证记录：错误签名返回 `IncompleteSignature`；正确签名 + 假 code 返回 `InvalidCode`（签名已被接受）。

### 2.1 核心组件

- `IopSigner`：纯函数签名，单元测试覆盖。
- `AlibabaClient.CallAsync(apiKey, params, files?)`：
  1. 从 API 注册表取路径与是否需 Token；
  2. 通过 `AlibabaTokenService.GetValidTokenAsync()` 拿 Token（过期前 5 分钟自动刷新，`SemaphoreSlim` 串行化）；
  3. 签名、发送（HttpClient 超时 30s）；
  4. `AlibabaResponseParser` 统一解析为 `AlibabaApiResult { Success, ErrorCode, ErrorMessage, RequestId, Json, DurationMs }`；
  5. 写 API 日志（access_token/sign/image_bytes 脱敏，响应截断 4KB）。
  网络异常/超时同样返回 `Success=false` 并记日志，不抛到 500。
- `AlibabaTokenStore`：用 ASP.NET DataProtection 加密落盘。
- `ListingMapper`：`ProductRecord → product_info` JSON（见 2.2）。

### 2.2 商品 → `product_info` 映射

| 本地字段 | Alibaba 字段 |
|----------|-------------|
| Title / Description / Keywords(空格连接) / Language / ModelNumber / BrandName | `basic_info.title / description / keywords / language / model_number / brand_name` |
| Images[0..5] | `basic_info.product_image[].image_url` |
| RemoteProductId（更新时） | `basic_info.product_id` |
| CategoryId / CategoryName / Attributes | `category_info.category_id / category_name / attributes[{attribute_name, attribute_value}]` |
| TieredPrices（为空则用 Price+MOQ 生成一档） / Currency | `trade_info.price{price_type:"TIERED", currency, tiered_price[{quantity, price}]}` |
| Stock / MOQ / Unit | `trade_info.inventory / moq / unit` |
| ShippingTemplateId / LeadTimeDays / WeightKg / Length×Width×Height | `logistics_info.shipping_template_id / tiered_lead_time[{quantity:MOQ, lead_time}] / weight / dimension` |
| AiOptimize | `ai_optimization_config.*_optimization_enabled` |

新建：`/alibaba/icbu/product/listing/v2`，返回 `result.data` = 商品ID。
更新：`/alibaba/icbu/product/update/v2`（`basic_info.product_id` 必填）。
状态：`/alibaba/icbu/product/status/get/v2`(product_id) → `online/pending/draft/failed` + `status_desc`。
库存：`/icbu/product/edit-inventory`(product_id, inventory)。
价格：`/icbu/product/edit-price`(product_id, price{…})。
上下架：`/alibaba/icbu/product/batch/update/status`(product_id_list, action=online|offline)。
类目预测：`/alibaba/icbu/category/predict/v2`(title, description, image)。
类目属性：`/alibaba/icbu/category/attribute/get/v2`(category_id)。
图片上传：`/alibaba/icbu/photobank/upload`(file_name, group_id, image_bytes 文件)。

## 3. 数据模型变更（ProductRecord）

新增：`BrandName, ModelNumber, Language, Unit, CategoryName, CategoryPath, TieredPrices[], ShippingTemplateId, WeightKg, LengthCm, WidthCm, HeightCm, AiOptimize, Images[]`（取代 MainImageUrl/DetailImageUrls，读取旧数据时自动迁移），`RemoteProductId, RemoteStatus, RemoteStatusMessage, LastSyncedAt`。

状态拆成两个维度，互不覆盖：
- `LocalState`（质检结果）：`Incomplete`（有阻断）/ `Ready`
- `PublishState`（远端）：`NotPublished / Publishing / Pending(审核中) / Online(已上架) / Offline(已下架) / Failed`

## 4. 关键流程

### 4.1 发布（后台队列）
```
POST /api/catalog/publish {productIds, aiOptimize}
  → 质检；全部阻断则直接返回 Blocked
  → 创建 PublishJob(Queued) → 写入 Channel → 立即返回 jobId
BackgroundService 逐个处理：
  RemoteProductId 为空 ? listing/v2 : update/v2
  成功 → 回写 RemoteProductId、PublishState=Pending → 调 status/get 刷新状态
  失败 → PublishState=Failed、RemoteStatusMessage=错误码+信息
  每个商品处理完更新 Job 进度
前端每 2s 轮询 GET /api/catalog/publish-jobs/{id} 直到完成
```
服务重启时，把 `Queued/Running` 的任务标记为 `Interrupted`，对应商品从 `Publishing` 恢复。

### 4.2 授权
- 一键授权：`GET /api/integrations/alibaba/oauth/url` → 跳转 → `/openapi/callback` 校验 state（DataProtection 加密 Cookie）→ 换 Token → 重定向回前端 `?alibabaAuth=success`。
- 手动：`POST /api/integrations/alibaba/token/create {code}`，前端支持粘贴整段回调 URL，自动提取 `code`。
- 本地 Vite 代理增加 `/openapi`；Docker nginx 增加 `/openapi/` 转发。

### 4.3 连接自检 `GET /api/system/diagnostics`
逐项返回 `{key, ok, message, fix}`：配置项、网关可达（无凭证请求应返回 `MissingParameter`）、签名有效（假 code 调 token/create，返回 `InvalidCode` 即通过）、Token 状态、回调地址、数据目录可写。

## 5. 配置

- 本地开发：API 启动时读取仓库根目录与项目目录的 `.env`（只补充未设置的键，忽略 `ASPNETCORE_*`），开发者无需手动设置环境变量。
- 默认值修正：`Alibaba:BaseUrl` 默认 `https://openapi-api.alibaba.com/rest`；API 注册表内置官方路径，配置可覆盖。
- 删除已无用的配置：`ProductPublishPath`、`DefaultRestMethod`、`ProductPayloadParameter`、`ApiVersion`、`PayloadParameter`（旧 TOP 协议遗留）。
- 生产环境必须设置 `Auth__AdminUsername/Password`，否则启动失败并明确提示（`.env.example` 同步补充）。

|------|------|------|
| POST | /api/auth/login、/logout；GET /api/auth/session | 会话 |
| GET | /api/system/diagnostics | 连接自检 |

| GET | /api/integrations/alibaba/oauth/url | 授权跳转地址 |

| POST | /api/integrations/alibaba/images/upload | 图片上传 |
| GET/POST/PUT/DELETE | /api/catalog/products[/{id}] | 商品 CRUD（SKU 冲突 409） |
| POST | /api/catalog/products/batch-delete | 批量删除 |
| POST | /api/catalog/import；GET /api/catalog/import/template.xlsx | 导入、模板 |
| POST | /api/catalog/quality-check | 质检 |
| POST | /api/catalog/predict-category | 批量类目预测并回填 |
