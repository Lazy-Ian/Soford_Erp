# 官网商品列表与详情一键同步（2026-10-28）

当前状态：功能和本地回归已完成，部署验收待补记。本说明取代旧文档中“保存 ERP 后官网自动更新”的商品发布方式。

## 操作

1. 管理员进入 ERP「商品」，编辑列表信息、图片、规格和描述并保存。
2. 勾选要同步的商品；也可以先筛选后不勾选，直接同步当前筛选范围内全部商品，范围覆盖所有分页。
3. 点击「一键同步官网」，核对数量并确认。列表信息和详情正文一起更新；结果逐项列出成功或未完成原因。
4. 通过「官网」列查看状态、同步时间和「查看官网」链接。之后修改 ERP 内容会显示「待同步修改」，再次同步才影响官网。
5. 从官网隐藏时，勾选商品，点击「官网下架」。可再次同步恢复，原详情链接保持稳定。

筛选项包括「官网待同步」「官网已展示」「官网未展示」。ERP「官网」页提供「去同步商品」入口；公司、联系人与 FAQ 仍在原资料页维护。

## 发布规则

- 管理员才能同步或官网下架，后端也检查权限；无需 Alibaba 授权，不调用 Alibaba 写入接口，不改变 Alibaba 发布状态。
- 新建或从 Alibaba 导入的商品不会自动公开；可以把资料完整的 ERP 新品同步到官网，无需先在 Alibaba 上架。
- 标题、有效图片、正数价格、起订量、币种、销售单位和详情正文必须有效。缺项跳过，保留该商品的上次官网版本；逐项说明原因。
- 本功能同步的是已保存在 ERP 的内容，不自动拉取 Alibaba 详情。描述为空时先编辑，或使用现有「拉取详情」后再同步。
- 手动同步按商品身份发布，同名不同商品不会再按标题静默去重；公共链接冲突会报错。
- 官网下架不删除 ERP 商品，也不影响 Alibaba。删除 ERP 商品则会同时移除对应官网商品。
- 官网仍执行字段转义及详情清洗，脚本、旧商业条款和 FAQ/联系段落不会原样展示。

## 数据与迁移

仍以 `products.json` 为唯一商品库，不生成静态产品目录或另一份商品库。每条商品中增加官网发布版本及元数据：

| 字段 | 用途 |
|---|---|
| `websiteSyncVersion` | 标记已采用显式同步流程 |
| `websitePublication` | 上次同步的列表 DTO 和清洗后的详情 HTML |
| `websiteStableId` | 固定公开链接，绑定 Alibaba 或官网下架后也保留 |
| `websiteSyncedAt` / `websiteSyncedBy` | 同步时间与操作者 |
| `websiteSourceHash` | 识别 ERP 内容是否发生变化，状态/质检时间更新不触发待同步 |

升级首次读取旧数据时，仅为旧规则下已展示的商品建立初始官网版本，保留原展示集合和链接；旧隐藏商品仍隐藏。初始版本标记为「系统迁移」。正常写盘后随原商品库持久化，重启后保持不变。

同步和官网下架在商品仓储锁内执行并原子写盘，成功后使目录缓存失效；读结果深复制。写盘失败清空内存缓存，不能将未持久化的版本暴露到官网。管理端列表不返回两份详情 HTML，保留轻量状态字段。

## 接口

| 接口 | 行为 |
|---|---|
| POST `/api/website/catalog/sync` | `{productIds: [...]}`，1–5,000 个去重 ID，管理员；同步列表及详情 |
| POST `/api/website/catalog/unpublish` | 同上，管理员；从官网隐藏 |
| GET `/public/products` | 读取已同步列表，保持现有返回结构 |
| GET `/public/products/{id}` | 读取相同发布版本的详情 |

管理接口返回既有 BatchResult：总数、成功、未完成及逐项原因；保存操作记录。请求必须明确传入商品 ID，空数组不会隐式同步全库。路径部署的 ERP API 位于 `/erp/api/*`，官网公开接口位于 `/soford/public/*`。
